# G925 Native v2.39 — steady 40 FPS optimization experiment

Goal: playable **40 FPS** (25 ms per title frame) on POCO X8 Pro Max,
not a nominal 60 FPS cap. This is an opt-in experiment and an Android
host build passing its tests is **not** proof of device-side FPS.

## Baseline from the 2026-11-21 native 180-frame capture

- Game interval: mean 37.72 ms (26.5 FPS equivalent), p95 47.99 ms.
- GPU: mean 21.78 ms (must still remain under the 25 ms budget).
- CPU command recording: mean 20.25 ms, native render callback 27.16 ms.
- Vertex optimizer uploads: bursty scenes can overwhelm background optimization.
- No evidence of shader compilation or GPU fence wait in these samples.
- The profiler adds overhead and CPU stages overlap. Never sum them.

## Implemented changes

1. **Opt-in G925 Native 40 FPS profile** in the launcher (Classic unchanged).
   Picks 720p/native upscaling, AA off, cap 40, draw distance 80%, density
   30%, console shadow size, reflection AA off, two guest run-ahead frames,
   16 ms Android hints/feedback, stable hint threads, dynamic distance,
   reflection FPS guard and the thermal guard.
   The button selects valid launcher cvars and uses the existing save path,
   which avoids duplicate CLI options. It leaves game files, saves and
   the stock system Vulkan driver intact. Before first application it backs
   up an existing graphics.txt to graphics-before-g925-40fps.txt.
   Draw distance, population, shadow quality and internal render resolution
   may look different; opting in makes this explicit.
2. **Vertex optimizer copy-backlog guard**: producer avoids allocating or
   copying new index ranges if pending queued source bytes would exceed
   32 MiB (or 512 jobs); the consumer returns those bytes to the budget
   when dequeuing. The existing renderer uses the original index order
   for rejected optimization jobs, so no geometry is discarded.
3. C++ randomized correctness checks for budget arithmetic; a Python
   integration test checks the source paths, every preset choice, the backup,
   and the native queue accounting. CI runs them before compiling the APK.

## Validation and expected outcome

Do not infer an FPS gain from these changes alone. The profile reduces GPU
pixel work and game-side CPU scene load, and the queue guard reduces potential
memory pressure / frame spikes, but the native renderer's ~4k draws remain.
On the phone, compare 2.37 to 2.39 under the same scene/saved game with
normal Play (no profiling) and capture the same 180-frame CPU/GPU trace.
Compare title mean and p95; record image quality, input delay and crashes.
40 FPS is only confirmed after repeated device tests with p95 <= 25 ms
in representative demanding scenes. If 40 is unsustainable, the title
is not forced to synthesize frames, and the user can restore their prior
graphics selections.
